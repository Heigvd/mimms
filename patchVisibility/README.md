# patchVisibility

Patches the `visibility` field of every object that has one, in a
`gameModel/gamemodel.json` and `gameModel/filesmeta.json`, to match the
equivalent object in `model/gameModel/`.

Scenario exports (and `_common`) set every variable, library, language and
file to `PRIVATE` on export, which is not what should end up in a
distributed zip. `model/gameModel/` is treated as the source of truth for
what each of those should actually be.

## How it matches objects

`refId` is regenerated by Wegas on every export, so it can't be used to
match an object between two different gamemodel.json files. Instead:

- In `gamemodel.json`, an object is identified by its `@class` plus whichever
  of `name` (variable descriptors), `contentKey` (libraries) or `code`
  (languages) it carries. Objects with none of those are left untouched —
  there is no way to tell them apart from `model`'s version.
- In `filesmeta.json`, entries are keyed by file path already, so matching is
  direct.

## How to run

```bash
node patchVisibility/patchVisibility.js <path/to/gameModel> [--verbose]
```

`<path/to/gameModel>` is the folder containing `gamemodel.json` and
`filesmeta.json` to patch in place. Used by `createZip.sh -p`.
